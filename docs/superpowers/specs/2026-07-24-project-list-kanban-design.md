# TeamFlow 项目列表与 Kanban 设计规格

## 1. 目标

在现有 Vue 3 认证基础上实现真实项目目录与项目 Kanban，让已登录用户能够：

- 查看自己参与的项目。
- 创建项目。
- 使用项目 ID 与邀请码加入项目。
- 进入项目三列看板。
- 按负责人和优先级筛选任务。
- 创建、编辑和删除任务。
- 在无筛选状态下进行列内和跨列拖拽排序。

本实现以当前 FastAPI 代码为唯一接口事实，不新增或重复开发后端项目、任务接口。

## 2. 本阶段范围

### 2.1 包含

- `/dashboard` 项目目录。
- 创建项目对话框。
- 加入项目对话框，字段为项目 ID 与邀请码。
- `/project/:id` 项目看板。
- 项目详情与成员加载。
- `todo`、`in_progress`、`done` 三列任务。
- 负责人、优先级筛选和清除筛选。
- 任务创建、完整编辑、删除。
- SortableJS 列内和跨列拖拽。
- 批量排序失败回滚。
- 加载、空状态、权限、未找到和请求失败状态。
- 桌面与移动端适配。

### 2.2 不包含

- 任务详情独立路由。
- 评论创建、查询和删除。
- 项目活动时间线。
- 项目统计和 ECharts。
- 项目设置与成员角色修改。
- 仅凭邀请码查找并加入项目的后端改造。
- 后端任务排序版本号、并发冲突检测或乐观锁。
- 服务端 JWT 撤销。

## 3. 现有后端契约

项目功能使用以下现有接口：

- `GET /api/projects`
- `POST /api/projects`
- `POST /api/projects/{project_id}/join`
- `GET /api/projects/{project_id}`
- `GET /api/projects/{project_id}/members`

任务功能使用以下现有接口：

- `GET /api/projects/{project_id}/tasks`
- `POST /api/projects/{project_id}/tasks`
- `GET /api/tasks/{task_id}`
- `PUT /api/tasks/{task_id}`
- `DELETE /api/tasks/{task_id}`
- `PATCH /api/tasks/batch-order`

加入项目必须同时提供 URL 中的 `project_id` 和请求体中的 `invite_code`。前端不把当前接口包装成“只输入邀请码即可加入”。

任务状态仅允许 `todo`、`in_progress`、`done`。优先级仅允许 `low`、`medium`、`high`。创建和完整更新任务均提交标题、描述、状态、优先级和负责人 ID。

## 4. 页面与路由

### 4.1 `/dashboard`

Dashboard 是项目目录，不承载 Kanban 或虚构统计。

- 顶部保留 TeamFlow 品牌、当前用户与退出。
- 页面标题为“项目工作区”。
- 主操作为“新建项目”和“加入项目”。
- 项目按后端返回顺序显示。
- 每个项目条目显示名称、描述、当前角色和创建时间。
- 点击项目条目进入 `/project/{id}`。
- 没有项目时显示创建或加入项目的空状态。
- 加载失败时保留页面结构并提供重试。

新建项目成功后，将项目加入 Pinia 列表并导航到新项目。加入项目成功后重新拉取项目列表，再导航到对应项目。

### 4.2 `/project/:id`

项目看板是独立的专注工作页。

- 顶部提供返回项目目录、项目名称、当前用户和退出。
- 工具栏提供负责人筛选、优先级筛选、清除筛选和新建任务。
- 主区固定显示待开始、进行中、已完成三列。
- 路由参数变化时重新加载项目详情、成员和任务。
- 项目切换期间不显示上一个项目的任务。
- `403` 显示无权访问并提供返回项目目录。
- `404` 显示项目不存在并提供返回项目目录。
- `401` 使用现有全局鉴权处理。

## 5. 项目目录交互

### 5.1 创建项目

创建对话框字段：

- 名称：必填，1 至 100 个字符。
- 描述：可选，最多 500 个字符。

提交期间锁定字段和按钮，防止重复创建。成功后关闭对话框并导航；失败时保留输入并显示规范化错误。

### 5.2 加入项目

加入对话框字段：

- 项目 ID：必填，正整数。
- 邀请码：必填，4 至 12 个字符。

`403` 显示项目 ID 或邀请码无效，`404` 显示项目不存在。重复加入由后端保持幂等，前端按成功处理。

## 6. Kanban 数据与展示

任务列表在 Store 中按状态分组，并按 `sort_order`、`id` 升序稳定排列。

列映射：

- `todo`：待开始。
- `in_progress`：进行中。
- `done`：已完成。

任务卡片显示：

- 标题。
- 优先级。
- 负责人用户名；未分配时显示“未分配”。
- 评论数量。

任务描述不在卡片中展开，避免卡片高度因长文本失控。所有用户生成内容使用普通文本插值，不使用 `v-html`。

## 7. 筛选

负责人和优先级筛选通过任务列表接口的查询参数执行，避免前端与后端过滤规则分叉。

- 负责人选项来自项目成员接口。
- 负责人筛选允许选择具体成员。
- 优先级筛选允许 `low`、`medium`、`high`。
- 清除筛选恢复完整任务列表。
- 筛选请求使用请求序号，旧请求不能覆盖较新的筛选结果。

任一筛选启用时禁用拖拽。原因是隐藏任务仍占据真实 `sort_order`，仅对可见任务重新编号会产生冲突或不可预测顺序。

## 8. 任务写操作

创建和编辑共用任务表单对话框，字段与后端 Schema 一致：

- 标题：必填，1 至 200 个字符。
- 描述：可选。
- 状态：必填。
- 优先级：必填。
- 负责人：可选，可明确设为未分配。

创建成功后将任务插入后端返回状态列，并按返回的 `sort_order` 排列。编辑成功后用后端响应替换 Store 中对应任务，并重新分组。

删除前显示确认对话框。只有后端返回成功后才从 Store 删除任务。后端失败时保留卡片并显示错误。当前 MySQL 评论外键没有级联删除，带评论任务可能删除失败；前端不提前移除，也不把失败显示为成功。

## 9. 拖拽排序

使用 SortableJS，不手写拖拽引擎。

- 无筛选时启用列内与跨列拖拽。
- 拖动结束后立即更新本地列顺序。
- 记录拖拽前任务快照。
- 为源列和目标列生成完整、连续、从 1 开始的排序载荷。
- 跨列任务在载荷中使用目标状态。
- 单次调用 `PATCH /api/tasks/batch-order` 提交所有受影响项。
- 排序请求进行时锁定所有列，不接受下一次拖拽。
- 成功后保留本地顺序。
- 失败后恢复快照并显示排序失败提示。

本阶段采用单批锁定提交，不使用 200ms 防抖连续提交。当前后端没有版本号或冲突检测，串行化前端排序事务更容易保持一致。

## 10. 前端模块边界

新增或扩展以下模块：

- `src/types/project.ts`：项目、项目成员、创建和加入载荷。
- `src/types/task.ts`：任务、状态、优先级、筛选和排序载荷。
- `src/api/projects.ts`：项目 API 与响应解码。
- `src/api/tasks.ts`：任务 API 与响应解码。
- `src/stores/projects.ts`：项目目录加载与写操作。
- `src/stores/board.ts`：当前项目、成员、任务、筛选和排序事务。
- `src/views/DashboardView.vue`：项目目录页面编排。
- `src/views/ProjectBoardView.vue`：项目看板页面编排。
- `src/components/projects/*`：项目条目、创建和加入对话框。
- `src/components/board/*`：工具栏、看板列、任务卡片和任务表单。

View 不直接拼装 Axios 请求。API 层负责 HTTP 与运行时响应校验，Store 负责业务状态和竞态控制，组件负责展示与用户事件。

## 11. 状态与竞态控制

项目 Store 使用独立加载票据，避免较旧项目列表响应覆盖创建或加入后的刷新结果。

看板 Store 对项目加载和筛选加载分别维护请求序号：

- 快速切换 `/project/:id` 时，旧项目响应被忽略。
- 快速切换筛选时，旧筛选响应被忽略。
- 项目加载开始时清除旧项目、成员和任务展示。
- 任务写操作按任务或全局提交状态防止重复提交。
- 排序事务具有独立锁和快照。

## 12. 错误处理

继续使用现有 `toApiError` 和全局 `401` 机制。

- 协议结构错误显示通用加载失败，不写入 Store。
- `403` 和 `404` 在项目看板展示专用页面状态。
- 创建、加入和任务表单错误显示在对话框内并保留用户输入。
- 排序失败展示看板级提示并回滚。
- 网络失败提供重试，不清除已经确认的项目目录数据。
- 错误消息不直接暴露数据库或服务端内部文本。

## 13. 响应式与可访问性

- 桌面端三列等宽，占满看板工作区。
- 移动端保持稳定列宽并横向滚动，不把三列堆叠为长页面。
- 工具栏在窄屏分行，控件具有稳定尺寸。
- 拖拽禁用状态同时通过视觉样式和说明文本表达。
- 项目条目和任务卡片支持键盘可达的明确操作。
- 图标按钮使用 Element Plus 或现有 Lucide 等价图标库中的熟悉图标，并提供可访问名称或工具提示。
- 对话框提交后将焦点留在错误字段或安全返回触发按钮。
- 文本允许换行或省略，不与按钮、标签重叠。

## 14. Element Plus 与依赖

继续选择性注册实际使用的 Element Plus 组件和样式，不引入完整组件包。

新增 SortableJS 作为拖拽核心依赖，并使用其正式 TypeScript 类型或官方类型包。除拖拽外不新增状态管理或 UI 框架。

### 15.1 自动测试

- 项目 API 成功响应、缺失字段和错误响应。
- 任务 API 成功响应、缺失字段、筛选参数和批量排序载荷。
- 项目 Store 加载、创建、加入、刷新和竞态。
- 看板 Store 项目切换、筛选竞态、任务分组、写操作和删除失败。
- 列内拖拽载荷。
- 跨列拖拽载荷。
- 排序失败快照回滚。
- 筛选状态下拖拽禁用。
- Dashboard 加载、空状态、错误、创建和加入。

- 路由 `/project/:id` 鉴权与参数变化。

每个功能遵循测试先行：先运行新增测试确认预期失败，再写最小实现并运行相关测试，阶段结束运行 lint、类型检查、完整测试和生产构建。

### 15.2 浏览器验收

使用真实 FastAPI 后端验证：

- 创建项目并进入看板。
- 使用第二个一次性账号、项目 ID 和邀请码加入项目。
- 项目目录正确显示角色。
- 创建三个状态的任务。
- 编辑标题、优先级和负责人。
- 负责人和优先级筛选。
- 筛选时拖拽禁用。
- 列内和跨列拖拽后刷新仍保持顺序。
- 删除无评论任务。
- 项目无权访问与不存在状态。
- 桌面和移动端无横向页面溢出、遮挡或文本越界；移动端看板区域允许受控横向滚动。

## 16. 已知风险

- 后端加入项目需要项目 ID 和邀请码，用户体验不如仅凭邀请码加入。
- 后端未校验任务负责人是否属于项目；前端只提供项目成员选项，但不能替代服务端完整约束。
- 后端排序无版本控制，多客户端同时排序时最后提交者覆盖前者。
- 带评论任务可能因为 MySQL 外键限制无法删除。
- 服务端退出仍不吊销 JWT。
- Node 22 是声明支持版本；当前环境若继续使用 Node 24，只能作为额外兼容信号，不能替代 Node 22 验证。
