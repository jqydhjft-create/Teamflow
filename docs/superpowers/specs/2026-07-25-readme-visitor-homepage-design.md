# TeamFlow 游客型 README 重写设计

## 背景

当前 `README.md` 以 `TeamFlow Backend` 为标题，主体是约 700 行的运行说明和逐接口文档。它能帮助后端联调，但无法让首次访问 GitHub 仓库的游客快速理解 TeamFlow 是什么、已经完成什么，以及如何在本地运行完整应用。

本次重写把 README 定位为项目首页。详细接口信息不再逐项复制到 README，开发者通过 FastAPI Swagger、技术文档、交接文档和设计文档继续深入。

## 目标读者

- 第一次打开仓库、希望快速判断项目用途的游客。
- 想了解技术栈、完成度和工程质量的开发者。
- 想在本地启动 TeamFlow 进行体验或二次开发的贡献者。

## 内容结构

README 按以下顺序组织：

1. 项目名称与一句话定位。
2. 当前可用能力和产品亮点。
3. 界面预览入口或截图占位说明。
4. 前端、后端、数据和测试技术栈。
5. 使用 SQLite 的最短本地启动流程。
6. Docker Compose 备选启动方式。
7. 精简项目结构。
8. 质量检查命令与当前测试基线。
9. Swagger、技术文档、交接文档和设计文档入口。
10. 当前实现边界和许可证状态。

全文以中文为主，目标长度为 150-220 行。使用短段落、平级列表和必要的命令块，不使用大量徽章、营销式口号或逐接口请求/响应示例。

## 项目定位

TeamFlow 描述为“面向小团队的全栈项目协作与 Kanban 任务管理应用”。README 必须明确它是可运行的前后端应用，不再使用只指向后端的标题或开场说明。

游客应能在首屏附近理解以下事实：

- 用户可以注册、登录并恢复当前会话。
- 用户可以创建项目，或通过项目 ID 和邀请码加入项目。
- 项目包含待办、进行中、已完成三列 Kanban 看板。
- 任务支持创建、编辑、删除、优先级、负责人和状态。
- 看板支持成员/优先级筛选、同列/跨列排序和键盘排序。
- 桌面端显示三列，移动端在看板区域内受控横向滚动。

## 界面预览

仓库当前没有正式截图资产。本次不生成虚假产品截图，也不引用依赖本机服务的 `localhost` 图片。

README 使用一个简短的“界面预览”说明，列出登录、项目工作区和 Kanban 看板三个主要页面，并提示后续可将正式截图放入 `docs/images/` 后替换该说明。不得使用无法渲染的图片链接或空白 Markdown 图片标签。

## 快速开始

默认推荐 SQLite 本地运行，以减少游客首次启动所需的外部依赖。步骤必须覆盖：

1. Python 3.11 环境与后端依赖。
2. 从 `.env.example` 创建 `.env`，并提醒替换 JWT 密钥占位值。
3. Alembic 数据库迁移和 Uvicorn 启动。
4. Node.js 22、pnpm 11、前端依赖和 `.env.local`。
5. Vite 前端启动。
6. 前端、API 和 Swagger 默认地址。

Docker Compose 作为备选方案保留，但不展开为部署手册。

## 技术事实边界

README 只描述当前代码已经实现的能力。评论、统计和活动日志应表述为“后端接口已存在，前端界面尚未接入”，不能列为当前 UI 功能。

质量基线采用重写前最近一次完整验证结果：

- 前端 24 个测试文件、499 项测试通过。
- 后端 30 项测试通过。
- 前端 lint、typecheck 和生产构建通过。

如果重写期间没有代码或测试变更，可以通过文档链接和命令核对验证 README，而不必把接口测试当作文档修改的必要条件。

## 详细文档去向

README 不再保留约 500 行的逐接口说明。替代入口包括：

- 运行中的 FastAPI Swagger：`http://127.0.0.1:8000/docs`。
- `TeamFlow_项目技术文档.md`。
- `PROJECT_HANDOFF.md`。
- `docs/superpowers/specs/` 和 `docs/superpowers/plans/`。

接口总览仅按认证、项目、任务、评论、统计和活动日志说明模块存在，不重复每个请求体和响应体。

## 已知边界

README 只保留游客和部署者最需要知道的限制：

- 服务端尚未撤销已签发 JWT。
- MySQL 下删除带评论任务可能受外键约束影响。
- 后端尚未强制负责人必须是项目成员。
- 多客户端并发排序采用最后写入者覆盖。
- 评论、统计和活动日志前端界面尚未接入。

## 许可证

仓库当前没有 `LICENSE` 文件。README 明确写明“暂未声明开源许可证”，不使用 `MIT`、`Apache-2.0` 或其他未经用户选择的许可证标签。

## 验收标准

- 标题不再是 `TeamFlow Backend`。
- 游客在前 40 行内可以理解项目用途、主要功能和前后端性质。
- README 中不存在乱码、失效图片、虚假演示地址或未实现功能。
- 本地 SQLite 启动步骤可从空环境按顺序执行。
- Node、pnpm、Python 和默认服务地址与当前代码一致。
- API 细节被压缩为文档入口，不再占据 README 主体。
- 当前测试数量、已知限制和许可证状态准确。
- Markdown 标题层级、代码块和相对文件链接有效。
